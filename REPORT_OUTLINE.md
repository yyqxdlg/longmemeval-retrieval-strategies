Primary independent variable:
- retrieval strategy: recency / semantic / hybrid

- task type: IE / MR / KU / TR

Dependent variables available from retrieval-only pilot:
- round-level Recall@k
- Recall-any@k (binary retrieval success)
- session-level Recall@k
- retrieval latency (median of 5 measured runs after 1 warm-up)
- retrieved token count, once the final generation tokenizer is fixed

Later, after answer generation:

Expected properties to state before looking at results:
- recall measures are bounded in [0, 1]
- Recall-any and answer correctness are binary paired outcomes
- latency is positive and may be right-skewed
- token count is a positive integer
- strategy effects may differ by task type

## 3. Preprocessing and Exploratory Analysis

Document these choices explicitly:

1. Parse `haystack_dates` and compute recency from the timestamp itself rather than list index.
2. Availability filtering is calendar-day based: exclude only sessions whose calendar date is strictly later than the question date; retain same-day sessions even if their HH:MM is later. Full timestamps are still used for recency ranking.
3. One dialogue round is one memory item.
4. Stella V5 1.5B is pinned to a fixed revision and used for both semantic and hybrid retrieval.
5. Primary Stella sequence length remains 512; report the fraction of memory rounds exceeding this token limit as a diagnostic / limitation.
6. Hybrid primary formula remains pre-registered: `0.5 * semantic + 0.5 * recency`.
7. Report the empirical SDs of semantic and recency components to diagnose scale imbalance.

EDA should include:
- number of observations per strategy and task
- missing values and completeness of paired cells
- round/session recall distributions and Recall-any rates
- latency distribution and outliers
- token-count distribution once available
- number of strictly-later-calendar-day sessions excluded and same-day-later sessions retained
- fraction of rounds exceeding Stella's 512-token limit
- hybrid semantic-score SD vs recency-score SD

## 4. Statistical Analysis

Because the same questions are tested under every strategy, all main comparisons are **paired**.

### Continuous / bounded retrieval outcomes

For round-level Recall@k, session-level Recall@k, latency, and token count:
- pairwise Wilcoxon signed-rank tests across the three strategies
- Holm correction for the three pairwise comparisons within each metric/scope family
- paired bootstrap 95% confidence intervals for mean differences

Run these comparisons:
- overall across all 20 pilot questions
- separately within IE, MR, KU, and TR as exploratory task-level checks

The task-level pilot tests have only about 5 paired questions per task, so their p-values must not be interpreted as strong evidence.

### Binary retrieval outcome

For `Recall-any@k`:
- exact McNemar pairwise tests
- Holm correction across the three strategy pairs
- paired bootstrap 95% CI for the paired proportion difference

This is an **exploratory retrieval-success analysis**. It is not the same as the Research Plan's pre-specified accuracy McNemar test.

### Answer correctness later

Once `answer_correct` is available:
- use exact McNemar pairwise tests for answer correctness, as pre-specified in the Research Plan
- apply Holm correction across the three strategy pairs
- report overall and task-level accuracy with 95% confidence intervals

### Top-5 vs top-10

If both k values are collected:
- report a comparison table for every strategy and outcome
- compare the same questions at k=5 vs k=10 within each strategy
- use paired Wilcoxon for continuous/bounded outcomes
- use exact McNemar for binary outcomes
- do not pool top-5 and top-10 rows into one estimate
